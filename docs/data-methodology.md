# 数据方法

## 原则

1. 每条菜品必须包含来源 URL、发布者或平台、访问日期和份量口径。
2. 数值字段只能是非负数字或 `null`，不能写 `"unknown"`。
3. 缺失字段不按零参与合计或排名。
4. “每份”和“每100克”不混用；页面按原始口径显示。
5. 第三方数据不能标成官方数据。
6. 实际门店分量、配方与批次可能变化，结果只代表公开标准口径的估算。

## 来源层级

| 层级 | 含义 | V1 用法 |
|---|---|---|
| 官方公开 | 品牌官方营养标识、报告或页面 | 优先，当前待逐条核验 |
| 第三方整理 | 标明品牌但由第三方数据库展示 | 当前 6 条演示数据 |
| 估算 | 相似菜品、用户输入或计算推断 | V1 不使用 |

`confidence` 不应只靠手写一个“高/中/低”。后续版本应由来源类型、发布时间、份量完整性和交叉核验状态共同推导。

## 数量口径

应用中的 `quantity = 1` 表示一份“来源记录单位”：

- 卤鸡腿：1 份，即 65 克；
- 葱油菜苔等：1 个单位，即 100 克；
- 三黑元气饭：1 份，但公开记录没有克重。

因此 V1 的数量调整是口径倍数，不是实际点餐份数的承诺。

## 合计规则

对每个已知字段：

```text
已知小计 = Σ（来源记录值 × 数量倍数）
```

如果任何已选菜品缺失该字段：

```text
完整合计 = null
```

食盐当量仅在钠完整时计算：

```text
食盐当量（g） = 钠（mg） × 2.5 ÷ 1000
```

该口径来自国家卫健委《餐饮食品营养标识指南》。

## 推荐规则

V1 枚举每个“1 主食 + 1 主菜 + 1 蔬菜”组合。评分使用连续函数，避免跨过一个阈值就突然加减大量分数。

推荐分数只比较当前候选，不代表绝对健康程度。默认目标是产品演示参数，不是为具体个人制定的医学建议。

## 更新流程

新增或修改一条营养数据时：

1. 保存可公开访问的原始来源；
2. 记录原页面的份量与单位；
3. 数值逐项录入，缺失项写 `null`；
4. 记录访问日期；
5. 在 `notes` 中说明缺口或异常；
6. 运行 `npm test`；
7. 在 Pull Request 中说明变更前后数值和来源。
